# 飞升对成长/OVR 的影响须经机制传导（删 ASC_DEV_DRAIN 隐藏暗扣）

## 背景

飞升（ascension）的难度曾由两条并行轴承担：一条经**机制**传导（转会节奏、市场保留、伤病概率、事件 odds、国家队门槛…），一条是**直接压 OVR 成长**——`ASC_DEV_DRAIN`（`data.ts` + `run.ts`）每个正成长季按档位抽 0.5→1.5 分进 `overallFrac` 跨季隐藏累积后扣 OVR，配 `sim.ts` 的"从严 min-of-rolls"（纯飞升触发）和"岁月催人 targetAge+2"。

诊断：第二条轴绕过了这个游戏本该有的因果链 `机制 → 选择 → 球队/数据/事件 → OVR`。它对玩家**不可感知**（`overallFrac` 不进 UI）、**不可对抗**（选什么都不影响每季暗扣）。这违反 `punishment-over-teaching`（惩罚要教导，先让玩家看见），也消解了飞升该有的"足球的难"——本该是"机会更稀缺、处境更残酷"，却退化成"你身体就是涨不到那么高"这种**先天设定**式的难，不是足球迷讲得出来的难。

它之所以存在，是因为 10 档命名机制大多不碰成长的连续轴，导致 2/3/5/7/8/9/10 档峰值挤一起（"死档"），drain 这条直线来兜各档巅峰的单调可感知递减——而单调性是 meta 经济 `ASCENSION_REWARD_CURVES`（A10 名义溢价 ×4.08）"高难高收益"成立的前提。

## 决定

**北极星铁律**：飞升对成长/OVR 的任何影响必须同时满足——①**经世界反应可感知**（diegetic——球员感到皇马在找我，不是看到「天花板 86」；代入而非上帝视角）②经选择可对抗 ③随档单调可感知递减。三者缺一，否决。这是 `机制→选择→…→OVR` 的形式化，也是防回归的尺。

> 铁律① 精确化（ADR-0005）：原写「玩家可感知」，后明确为「**经世界反应可感知（diegetic）**」。绿茵轮回是球员生涯代入，不是上帝视角经理游戏——所有因果须经世界反应（大俱乐部邀约、教练说你到顶了、身体恢复变慢）让玩家感知，而非经 UI 数字（培养上限标、衰退期标签）。FM 显示 CA 适合经理游戏；本作暴露数字会出戏。

**删除** `ASC_DEV_DRAIN`（隐藏暗扣），以一条**可见的天花板轴**替代它的单调兜底职责：

- 新增 `ASC_CEIL_DROP[0..10]` 天花板偏移，作用于 `sim.ts applyCeiling` 的天花板值（**不**改 `devEnvRep`，避免连带压青训期 `CLUB_YOUTH_MULT`——青训期无转会机会，连压会制造新的不可对抗口子）。L0-L4 = 0（成长判定类档位主题非"俱乐部培养上限"，降天花板语义错位），L5-L9 单调递减，L10 沿用既有的 `rep-1` 全面降级（已含天花板下降，不再额外加，避免双扣）。
- 天花板是玩家可推理的（"这家俱乐部顶到 X，我得转会"），可见；想涨到 90+ 必须转会去更大俱乐部，而 L7/L8 让转会更难——经**转会选择**传导，可对抗。

**改造从严（L1）**：min-of-rolls 从"纯飞升触发"改为"**角色门控**——只在 `isLowRole`（板凳/轮换）时触发，主力/半主力放过"。叙事自洽（上场才涨，豪门板凳最废），可对抗（转会去能当主力的队）。`bigClubBench` 在高飞升段加重已就位。

**岁月催人（L4）**：机制不动，加轻量可见性——英雄卡/生涯进度条的年龄段标"衰退期"（28 起暗色，飞升≥4 提前到 26 并变红）。只标足球概念，不解释机制。**本轮暂未落地，拆为后续独立 UI 工作**（需过 impeccable/ui-ux-pro-max 设计门）；核心机制（删 drain + 天花板轴 + 从严门控）先交付。岁月催人当前维持"年龄+OVR 趋势隐性可见"，满足铁律①的下限。

**文案**：只更新语义变了的档——L1 改为"板凳球员成长判定取两次较低值，主力不受影响"；L4 维持原描述配 UI 标记。其余 8 档不动。文案工作走 `team-narrative`。

**标定**：理论估 `ASC_CEIL_DROP` 初值（drain 累计效应反推天花板等效量级，仅作起点），重跑 `ascension-probe`→`ascension-reanchor`→`ascension-economy-check` 重锚 `ASCENSION_REWARD_CURVES`/`ASCENSION_UNLOCK_REQ`→`regress:bless`。验证：各档峰值单调递减 + 高飞升非最优刷分位（economy 5 条绿）+ difficulty-smoke 15 阈值 + regress 三层绿。

## 考虑过的替代方案

- **路 A 纯机制+重锚，不设任何连续兜底**：最贴链，但历史已证各机制档单独压不动 raw 到单调（死档就是这么来的），经济膨胀风险最高。否决。
- **路 B 新增"训练低效"可见状态/事件兜底**：回到链，但增加事件复杂度（complexity-masquerading-as-depth），且"每季概率状态"稍不留神又变一道隐藏 roll。否决，留作退化兜底。
- **通过降 `devEnvRep` 实现天花板轴**：会连带压青训期 `CLUB_YOUTH_MULT`（青训期无转会机会，不可对抗），且 `SQUAD_BASE` 整级跳变是断崖非递减。否决，改独立偏移。
- **从严按俱乐部 rep 门控**：会让"去小俱乐部当主力"成为高飞升最优解，与"飞升该让攀升更难"矛盾。否决，用角色门控。

## 后果

- **预期正面**：飞升的难全部经可见、可对抗的机制传导；删掉隐藏暗扣满足 `punishment-over-teaching`；一条可见轴替代多条隐藏直线满足"复杂度≠深度"；10 档命名/主题全保留，保品牌。
- **已知代价**：天花板压"峰值高度"，drain 压"每季速率"，效果模型不同——标定后单调性可能不如 drain 线性保证，需微调偏移曲线。不是所有档都必须峰值不同（L3/L9 的难在体验不在峰值）。
- **退化兜底**：若标定证明纯天花板轴压不出单调，退化方案是保留一个极小连续项但**必须可见化**（如 UI 显示"飞升抑制成长 X%"），铁律禁止回到隐藏暗扣。
- **叙事更新**：L1 文案语义变化需走 `team-narrative`；衰退期 UI 标记需过 `impeccable`/`ui-ux-pro-max` 门。
