# 重构手法索引 — 61 式（按书章节分组）

来源：《重构：改善既有代码的设计》第 2 版，第 6–12 章。
处方只允许引用这里的名字；编号即本表章节号（smells.md 中引用同此编号）。
每式一句话说明"何时用它"。

## 第 6 章 第一组重构

- **6.1 提炼函数（Extract Function）** — 一段代码有独立意图时，提炼为以"做什么"（而非"怎么做"）命名的函数；哪怕只有一行，只要它需要注释来说明。
- **6.2 内联函数（Inline Function）** — 函数本体和名字一样清晰时，去掉这层无谓的间接。
- **6.3 提炼变量（Extract Variable）** — 给复杂表达式的一部分起名，让计算步骤可读、可断点。
- **6.4 内联变量（Inline Variable）** — 变量名并不比表达式本身更有表达力时，消去它。
- **6.5 改变函数声明（Change Function Declaration）** — 改函数名或参数列表；对已发布接口用迁移式做法：旧签名转发新签名，逐步废弃。
- **6.6 封装变量（Encapsulate Variable）** — 把数据访问收口到函数，先看得见修改点，再谈控制与演进。
- **6.7 变量改名（Rename Variable）** — 最常用的重构；好名字省下未来猜谜的大把时间。
- **6.8 引入参数对象（Introduce Parameter Object）** — 总是结伴出现的参数组合成一个结构，缩短签名并为行为聚集创造家园。
- **6.9 函数组合成类（Combine Functions into Class）** — 一组函数围着同一批数据打转时，把函数和数据收进一个类。
- **6.10 函数组合成变换（Combine Functions into Transform）** — 多处对同一数据做派生计算时，统一在一个变换函数里算好、随数据一起传递。
- **6.11 拆分阶段（Split Phase）** — 一段代码处理两个不同上下文时，拆成先后阶段，以中转数据结构衔接。

## 第 7 章 封装

- **7.1 封装记录（Encapsulate Record）** — 可变的裸记录换成类，隐藏存储细节。
- **7.2 封装集合（Encapsulate Collection）** — 取值函数返回集合副本或只读视图，修改收口到宿主类的 add/remove。
- **7.3 以对象取代基本类型（Replace Primitive with Object）** — 领域概念（钱、电话号码、范围）从裸 number/string 升级为自有类型。
- **7.4 以查询取代临时变量（Replace Temp with Query）** — 临时变量改为查询函数，为提炼函数扫清障碍。
- **7.5 提炼类（Extract Class）** — 一个类承担两个类的职责时，把相关字段与函数拆出新类。
- **7.6 内联类（Inline Class）** — 一个类不再赚回自身成本时，并回它的使用者。
- **7.7 隐藏委托关系（Hide Delegate）** — 在服务对象上建转发函数，客户端不再穿透到委托对象。
- **7.8 移除中间人（Remove Middle Man）** — 转发函数多到失控时，让客户端直接与真正负责的对象打交道。
- **7.9 替换算法（Substitute Algorithm）** — 找到更清晰的算法时，整块换掉函数本体。

## 第 8 章 搬移特性

- **8.1 搬移函数（Move Function）** — 函数与另一个模块的数据/函数交流更频繁时，搬去它该在的地方。
- **8.2 搬移字段（Move Field）** — 数据的归属错了，行为怎么搬都别扭；先搬数据。
- **8.3 搬移语句到函数（Move Statements into Function）** — 每个调用点都重复的前后语句，收进被调函数。
- **8.4 搬移语句到调用者（Move Statements to Callers）** — 原本共同的行为开始分化时，把分化部分搬回调用端。
- **8.5 以函数调用取代内联代码（Replace Inline Code with Function Call）** — 一段代码做的事已有现成函数时，直接调用它。
- **8.6 移动语句（Slide Statements）** — 相关代码靠近摆放，为提炼做准备。
- **8.7 拆分循环（Split Loop）** — 一个循环做几件事时拆开，一循环一事，各自可独立修改（性能疑虑留给实测）。
- **8.8 以管道取代循环（Replace Loop with Pipeline）** — filter/map 管道让被处理元素与处理动作一目了然。
- **8.9 移除死代码（Remove Dead Code）** — 不再被用的代码直接删；版本控制记得它。

## 第 9 章 重新组织数据

- **9.1 拆分变量（Split Variable）** — 一个变量被赋值多次、承担多个职责时，一职责一变量。
- **9.2 字段改名（Rename Field）** — 记录结构的字段名是理解数据的关键，值得改好。
- **9.3 以查询取代派生变量（Replace Derived Variable with Query）** — 能算出来的值不要存——手工维护的派生数据是最刺鼻的可变数据。
- **9.4 将引用对象改为值对象（Change Reference to Value）** — 不可变的值对象更易推理，可整体替换。
- **9.5 将值对象改为引用对象（Change Value to Reference）** — 需要共享且同步更新同一实体时，改用引用 + 仓库。

## 第 10 章 简化条件逻辑

- **10.1 分解条件表达式（Decompose Conditional）** — 条件、then、else 各自提炼成以意图命名的函数。
- **10.2 合并条件表达式（Consolidate Conditional Expression）** — 结果相同的一串检查合并成一个条件（然后往往可以提炼）。
- **10.3 以卫语句取代嵌套条件表达式（Replace Nested Conditional with Guard Clauses）** — 非常态情况提早返回，让主干路径一眼可见。
- **10.4 以多态取代条件表达式（Replace Conditional with Polymorphism）** — 同样的条件分支散布多处时，用多态（TS 中常为判别联合 + 穷尽检查）消灭重复 switch。
- **10.5 引入特例（Introduce Special Case）** — 对某个特殊值（常是 null）的检查散布各处时，为它建一个带默认行为的特例对象。
- **10.6 引入断言（Introduce Assertion）** — 把"此处必然成立"的假设显式写出，兼作活文档。

## 第 11 章 重构 API

- **11.1 将查询函数和修改函数分离（Separate Query from Modifier）** — 有返回值的函数不应有可观察副作用；查询随便调，修改要小心。
- **11.2 函数参数化（Parameterize Function）** — 几个函数只差字面量时，合并为一个带参数的函数。
- **11.3 移除标记参数（Remove Flag Argument）** — 控制内部分支的 boolean 参数拆成显式的两个函数。
- **11.4 保持对象完整（Preserve Whole Object）** — 从一个对象抽出多项数据传参时，改传整个对象。
- **11.5 以查询取代参数（Replace Parameter with Query）** — 参数可由函数自行查得时去掉它，简化调用方。
- **11.6 以参数取代查询（Replace Query with Parameter）** — 反向：函数内部的查询造成讨厌的依赖时，改由调用方传入（换取引用透明）。
- **11.7 移除设值函数（Remove Setting Method）** — 字段只应在构造时赋值的，删掉 setter，宣告不可变。
- **11.8 以工厂函数取代构造函数（Replace Constructor with Factory Function）** — 需要比构造函数更灵活的创建逻辑（改名、返回子类、缓存）时。
- **11.9 以命令取代函数（Replace Function with Command）** — 复杂函数升级为命令对象，参数和临时变量变字段，可拆解、可复用中间状态（过长函数的杀手锏）。
- **11.10 以函数取代命令（Replace Command with Function）** — 反向：命令对象不够复杂时降级回普通函数。

## 第 12 章 处理继承关系

- **12.1 函数上移（Pull Up Method）** — 子类间重复的函数上移到超类。
- **12.2 字段上移（Pull Up Field）** — 子类间重复的字段上移。
- **12.3 构造函数本体上移（Pull Up Constructor Body）** — 子类构造函数的公共部分上移。
- **12.4 函数下移（Push Down Method）** — 只与部分子类相关的函数下移到那些子类。
- **12.5 字段下移（Push Down Field）** — 同上，针对字段。
- **12.6 以子类取代类型码（Replace Type Code with Subclasses）** — 类型码影响行为时引入子类，为多态铺路。
- **12.7 移除子类（Remove Subclass）** — 子类差异小到不值得存在时，用超类字段表达差异。
- **12.8 提炼超类（Extract Superclass）** — 两个类做类似的事时，把共同点提到共同超类。
- **12.9 折叠继承体系（Collapse Hierarchy）** — 超类与子类差异不大时合而为一。
- **12.10 以委托取代子类（Replace Subclass with Delegate）** — 继承轴只有一根且耦合过紧时，改用组合；"优先使用组合而非继承"的落地式。
- **12.11 以委托取代超类（Replace Superclass with Delegate）** — 子类只想要超类的部分能力时，划清界限改为持有委托。
