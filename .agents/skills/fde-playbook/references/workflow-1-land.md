# FDE 工作流·阶段 1–3：找对问题 → 赢得客户 → 激活部署（详细笔记）

源：《前线部署工程师》第 2–4 章。

## 阶段一：解决正确的问题（第 2 章)

**目标**：在写第一行代码之前，确认这个客户的这个问题既值得解决、也解决得了——「在错误的问题上，一切执行力都是浪费」。

**关键活动（按序）**
1. 用**影子工作法**下到现场，跟完真实用户真实的一天（不是采访，是坐在旁边看）；
2. 重点观察「变通」而非「流程」——每个变通背后都是一次系统失败；
3. 绕过「翻译过的痛点」（信息部译成技术需求、采购译成合规条目），直达疼痛神经末梢；
4. 过 **PSF 三关**（必须在客户现场过）；
5. 先建考题（评估题库）再谈上线，此后每天重跑旧题防模型悄悄退步；
6. 设计并跑一次 **MVD**，周级死线内向业务方演示，当场决定放大/调整/散伙；
7. 边界上执行「读旧写新」。

**关键方法论/框架**
- **PSF（Problem-Solution Fit）三关**：①痛点检验——是不是「某个具体的人的具体的痛」（麦格鲁标准：解决 CEO 最关注的五个问题之一；Sierra 默勒标准：只接「真的难的」和「真的有业务影响的」）；②经济性检验——这个问题每周吃掉多少人时、出错赔多少；③可行性检验——数据在哪/什么状态、准确率门槛是多少（90% + 人工复核常是最优解）。
- **MVD（Minimum Viable Deployment）三条军规**：①真实数据，没有例外；②缩小的是范围，不是价值（砍覆盖面，不砍深度）；③定死截止时间（以周计），倒逼诚实取舍。
- **AIP 训练营（MVD 的工业化）五动作**：第 0 天锁定核心战场 → 第 1 天接入建本体 → 第 2–3 天背靠背构建 → 第 4–5 天高管亲手点、当场拍板。无平台底座者用**两周冲刺验证**简化版（客户侧三项配合：能拍板的业务负责人在场、懂数据的内部接口人全程陪同、真实数据权限第 1 天就位）。
- **拒绝的三条防线**：①概念验证必须有「毕业标准」；②警惕三类高危信号（无主之地／只许看不给碰／宇宙级需求，中两条即警惕）；③把「现在不做」翻译成「什么时候做」，给拒绝留台阶。
- **读旧写新**：数据层深度兼容旧系统，架构层绝不寄生，流程层顺从人的习惯而非系统的习惯。
- **「永远在选题」**（Ramp 第一原则）：不对客户要求照单全收。

**产出物**：一句话的单点问题定义 + 一个数的验收指标；核心战场与量化靶子；数据/权限/脱敏方案（第 1 天到位）；评估题库与基线分数；跑在客户真实数据上的可部署原型；写明毕业与散伙两种后续的验证方案。

**反模式**：PoC purgatory（无限期、无指标、无裁判的概念验证坟墓）；用脱敏样例或自造演示数据验证（「坟墓的第一块砖」）；把 MVD 做成阉割版大方案；把「最小验证」拉成六个月；解决「演示效果好的问题」而非「值钱的问题」（超半数预算投前台，回报在后台）；把验证冲刺开成技术选型大会（验证期选型唯一标准是快）；在总部会议室对着二手信息做判断；只「问」不「看」的传统调研。

**成功标准**：三关全部在现场过；客户带自己的真实业务数据来；能拍板的业务负责人在场；周级内业务高管亲手用上活的软件并当场决定进退；毕业指标数值达成。

**金句**：「写第一行代码之前，先得确保你在解决正确的问题。」（2.1）／「与外部专业供应商合作的项目，成功率约为内部自建的三倍——他们输不起。」（2.1）／「价值没法从上十个客户那里继承，只能在这一个客户身上重新验证。」（2.5）／「人对『哪里不对』的判断力，远强于对『要什么』的想象力。」（2.7）／「我们宁可你晚一点开始，也不希望你在错的时机开始。」（2.3）

## 阶段二：赢得客户（第 3 章)

**目标**：在一个被辜负过无数次的市场里做到「让人信」，把验证过的单点价值变成一纸合同和一段真正开始的关系。

**关键活动（按序）**
1. 按灯塔价值筛客户，同时排查「需求蝗虫」；
2. 从最笨的事做起：人到场 → 手弄脏 → 先做仆人再做导师；
3. 进场尽职调查，画出五份地图（1–2 周，「回声」与「三角洲」分头进行、每日对表）；
4. 用技术内容与开源资产做「专业信任的预售」；
5. 提前把采购/法务/安全三道闸门当交付的一部分来打；
6. 借生态伙伴的肩膀；
7. 按战略价值排期，把等待期产品化；
8. 写倒金字塔提案与带毕业标准的验证方案。

**关键方法论/框架**
- **灯塔客户**三重战略价值：最强销售资产／决定产品基因（前十个客户在事实上塑造产品，故需 ICP 理想客户画像）／质量比数量重要一个数量级。附加检验：**成功后他愿不愿公开站出来**——不愿替你说话的灯塔价值打对折。
- **需求蝗虫**三特征：偏离战略沉淀不下能力／把 FDE 当廉价外包按人头派活／内部政治消耗巨大。
- **「在规模上做不可规模化的事」**（麦格鲁）——笨办法三层次（人到场／手弄脏／先仆人后导师）换三样战略资产：组织真实地图、数据环境真相、「自己人」身份认证。
- **进场尽调五份地图**：数据地图（重点不是「有什么」而是「哪个被信任」）、流程地图（标注耗时最大/出错代价最大/情绪最激烈三个点位）、组织地图（找「知识枢纽」）、系统地图（客户发版要走几周流程）、**政治地图**（动了谁的奶酪，并给受损者安排「新生路」而非死路）。
- **企业采购信任排序**：厂商宣传 < 分析师报告 < 同行公开案例 < 同行私下推荐。**可传播叙事三要素**：一个具体数字、一个具体的人、一个具体反差；交付结束时给支持者备好一页纸/三张图/30 秒版本。
- **内容三军规**：写「战壕视角」不写「展台视角」／方法论开源制造「被引用的资格」／让客户的内部支持者成为内容里的英雄。
- **三闸门通关术**：采购关给「可交差」的工具（分阶段报价、市场基准、结果承诺）；法务关把数据处理协议当产品打磨（预置模板、模型使用声明、分级事故责任）；安全关用**预答白皮书**抢出两个月（八成问卷可复制粘贴，响应速度本身即成熟度信号）。
- **生态三类伙伴**：云厂商（可用既有承诺消费额度采购）／咨询与集成商／**客户的客户**（交付时预埋「可再交付性」）。
- **排期三原则**：按战略价值而非合同金额排（决策矩阵＝灯塔价值 × 学习价值）／把「等待」产品化（数据准备清单、组织预热、远程诊断，可缩短进场后周期三分之一）／永不承诺超越产能的并行。**红线**：单份合同十万美元以上，模式才成立。
- **提案倒金字塔四层**：①业务结果一段话说完（客户语言）②价值验证路径（指标、测量方法、基线、每阶段退出机制——「我们敢被检验」）③交付方法（含客户需配合事项）④风险与对策（我们想过会怎么死）。
- **混合交付**：必须物理在场的三类场景——关系建立初期、高强度共创、政治敏感期；远程更好的是深度编码、文档沉淀、常规迭代。

**产出物**：ICP 与灯塔名单；五份地图；一页纸客户叙事包；安全白皮书与预置法务模板；四层提案 + 写明毕业/散伙的 PoC 方案；排期矩阵与等待期经营包；开源快速上手包。

**反模式**：按合同金额排期；接下预算诱人的需求蝗虫；带「我们来拯救你们」的姿态进场；提案通篇讲「我们要做什么」而非「你将得到什么」；回避风险章节；含糊的验证方案（等于给概念验证坟墓签发开工许可）；用精心准备的样例数据表演演示；生意好时忍不住多接单；全程不见面的项目；招标书写「人工智能赋能全集团」（吓跑最懂行的，吸引最敢吹牛的）。

**成功标准**：灯塔愿意联合发布案例、行业会议现身、接待参访，甚至把你的方法论当自己的行业领导力展示；出现同行私下推荐；安全问卷两周交卷；合同越过十万美元红线；客户明确要求「不只要供应商，要一个能共建的团队」。

**金句**：「你交付的不是软件许可证，是客户高管在同行饭局上的一句『他们真的懂行』。」（3.3）／「灯塔战略的死穴不是找不到灯塔，是让灯塔在你手里熄灭。」（3.3）／「两周尽调省下的，是三个月在错误战场上的狂奔。」（3.4）／「验证方案敢写多狠，取决于背后的账算得多清。」（3.9）

## 阶段三：激活部署（第 4 章)

**目标**：让目标用户群体在日常工作中形成对系统的稳定使用习惯——不是演示会上鼓掌，是撤场三个月后没人催、系统依然被高频使用。

**关键活动（按序）**
1. 把终点从「验收单」改为「客户行为的改变」；
2. 进入热修复节奏，以天甚至小时计响应；
3. 从真实案例长出评估体系，拉业务方当评委，再接进生产回路持续监测；
4. 用四种手法拆掉使用门槛；
5. 把集成当战役打，数据问题先于模型问题解决；
6. 经营三组人物做变革管理；
7. 把自己的交付工作自动化，让每次交付为下次修路。

**关键方法论/框架**
- **上线 ≠ 激活**：上线走完的只是采购与验收的行政流程，激活发生在用户行为里。失败的典型状态是「双轨制」——官方系统空转，**影子人工智能（shadow AI）**横行（约四成企业提供官方订阅，九成员工在用个人工具）。
- **激活要过的三关**：不顺手（比旧习惯多一步就没人用）／不可信（错一次信任清零）／与我无关。
- **热修复文化三执行要点**：①反馈必须直达写代码的人，中间不隔传话筒（最好人就坐在用户旁边）；②迭代优先级按「使用阻塞度」排，不按「功能重要度」排；③每天收工问一句「今天的改动，让用户明天的哪一刻更顺了」。
- **评估体系（evals）三步**：①从客户真实案例里长出来（把业务专家的隐性判断力显性化为标尺）；②让业务方成为评委（并排对比、优劣标注、定期评审会）；③接到生产回路上，持续采样、分数下滑即告警。要点：用户最敏感的不是平均质量，是质量的稳定性。
- **降门槛四手法**：①寄生在用户已有界面里（表格插件、邮件、手持终端）；②默认值里藏着激活率（预置模板、基于客户数据的预填示例、第一次打开就有属于他的待办）；③把「问人工智能」翻译成「点按钮」（对话式留给探索，按钮式留给日常）；④先做「副驾驶」再谈「自动驾驶」——但须警惕**审批疲劳**（约 93% 权限请求被直接批准），边界要挪到系统底层「默认拒绝」，而非指望人每次认真点允许。
- **集成战争四要点**：①当战役打，不当杂务办，最硬的骨头最早啃；②数据问题先于模型问题（垃圾进垃圾出；Palantir 的解法是**本体 ontology**——带业务语义的数据层，厘清哪个字段权威、哪个版本有效、谁有权看什么；数据治理贯穿项目始终）；③用人工智能打人工智能的集成战争（浏览器智能体从无接口老系统取数、字段映射交给模型）；④知道什么时候绕开而不是攻克（影子读取／人工摆渡／宣告隔离）。
- **变革管理三组人物**：**支持者**（给他能讲的材料、给他战功、给他安全感；Lowe's 制度化为「高级副总裁级业务负责人不入局就不做」）；**影响者**（无冕之王，让他们成为共同作者，破解「不是我做的东西我不用」）；**受损者**（提前设计出路：释放的人力导向高价值工作并公开承诺不裁员，把「守门人」转型为「教练」）。
- **交付自动化四类资产**：部署模板（IaC 一键拉起）／集成组件库（写一次处处复用）／检查清单文化（安全、准入、撤场交接——把「依赖个人经验」变成「依赖组织记忆」）／自动化汇报。配套：把质量检查也交给机器（自动化测试产能是敢做日级迭代的前提）。

**产出物**：评估集 + 生产回路的持续打分与告警；一键动作按钮集与预置模板；系统地图与分级集成排期；统一语义层/本体；受损者出路方案与不裁员承诺；部署模板、连接器库、三张检查清单、半自动周报。

**反模式**：把验收单当终点、交完就走；反馈经客户成功→产品经理→排期层层转（每传一手丢一半上下文）；按功能重要度而非使用阻塞度排期；工程师自己编评估集、把评估当工程自嗨工具；把上线分数当终点；要求用户登录崭新门户、让用户面对空白首屏自己组织提问；对高风险流程一步到位推自动化，且只靠「人来确认」兜底；把集成写成计划里的一行「系统对接：2 周」；先上模型后治数据；工程师自尊心驱动地攻克每一座遗留堡垒；忽视受损者（他们会成为最顽强的地下抵抗者与续约时的反对票）；把每次交付都做成不可复用的一次性劳动。

**成功标准**：**终极检验只有一条：团队撤场后，系统是否依然被使用**——在场时热火朝天、撤场后迅速冷却，那不是激活，是伴舞。辅助信号：三个月后无人催仍高频使用；解决率曲线按季度持续爬坡（23%→51%→86% 一类的完整上升曲线）；扩张的每一步都发生在上一步使用数据被公布之后（BBVA 3300→1.1 万→12 万）；用户反而越来越少需要求助。

**金句**：「上午提的问题下午就改好，比任何承诺都更能攒下用户的信任。」（4.2）／「不在卖场地板上待过，就没法为门店团队做设计。」（4.4，Lowe's）／「工程师的自尊心总想攻克每一座堡垒，而 FDE 的判断力，恰恰体现在选择战场——项目要的是客户结果，不是技术全胜。」（4.5）／「一个被善待的支持者，胜过十场产品宣讲会。」（4.6）／「人海的问题不在人多，而在每个人都在做不可复用的一次性劳动。」（4.7）

## 三阶段串联的主线

第 2 章用 PSF/MVD 确保问题正确且价值可验证 → 第 3 章把验证过的单点价值换成合同与信任（灯塔、五份地图、三道闸门）→ 第 4 章把合同变成被真实使用的习惯（评估体系、降门槛、变革管理），并把每次交付沉淀成下次的脚手架。回指关系：第 2 章的三类高危信号在第 3 章筛灯塔时复用；第 3 章政治地图里的「受损者」在第 4 章变革管理里兑现；第 2 章的「先建考题」在第 4 章长成评估体系的完整闭环。
