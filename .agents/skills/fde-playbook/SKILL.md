# FDE Playbook：角色定位与工作流程

本 skill 是《前线部署工程师》一书的操作性提炼。用它回答「FDE 是什么/怎么干」类问题、以 FDE 视角审视一次交付计划，或为 FDE 相关的产品/组织设计提供框架。需要更深的细节（完整框架清单、金句出处、指标口径）时，读 `references/` 下对应文件。

## 一、角色定位

**定义**（鲍勃·麦格鲁）：「前线部署工程师，是一个驻扎在客户现场、填补『产品能做的事』与『客户需要的事』之间鸿沟的工程师。」三个关键词：

- **驻扎现场** = 工作语境嵌入客户（进客户的群、读客户的数据、认识「知道流程为什么是这样的那个人」），不等于物理常驻。
- **鸿沟** = 存在理由：产品开箱即用的地方不需要 FDE；鸿沟越深（情报/金融/制造/医疗/法律）越需要。
- **工程师** = 最要紧的限定词：**写的是生产环境的代码，不是报告**。

**双重使命**：一头向客户交付结果，一头向公司输送产品情报。现场学到的东西必须回流产品——这是 FDE 区别于外包/咨询的机制核心（Palantir 把现场定制记在「产品发现」而非服务成本上）。心智模型：**砾石路 → 高速公路**——FDE 在现场修通往价值的砾石路，平台团队把值得复用的路硬化成高速公路。

**与相邻角色划界**：

| 对比 | 划界 |
| --- | --- |
| vs 售前 | 售前签约前结束、目标赢单、作品是幻灯片；FDE 签约后进深水区、目标赢结果、作品是生产系统。薪酬里销售提成占比高的多半是换头衔的售前 |
| vs 驻场外包 | 外包按工时算钱、从零现写、人走系统停；FDE 按阶段交付按结果验收、带平台底座来做工程、做完会走而能力留在系统里。FDE 必须绑定一个平台，否则退化为外包 |
| vs 咨询 | 顾问交建议、不对执行负责，生意建立在客户持续的需要上；FDE 对系统最终运转负责，**客户哪天不再需要你，才说明你干成了** |
| vs 产品工程师 | 产品工程师面对抽象用户（画像/DAU）；FDE 面对具体客户。Palantir 划分：平台工程师 =「一种能力服务多个客户」，FDE（Delta）=「一个客户调动多种能力」 |

**核心信条**：一切用结果说话——开工前先和客户定义「什么叫成」（靶子要像「排产冲突降 30%」，不是「探索 AI 赋能」）；里程碑不在系统上线那天，**在客户团队改变工作方式那天**；先救活眼前这个客户（「去他的可泛化性」——复用是平台团队的事）；凌晨两点部署挂了，你修好它，句号。

**能力模型**：① 够宽的技术通才（全栈 + 数据管道 + 大模型脾气 + 企业「水电煤」：SSO/权限/合规）；② 把技术翻译成业务结果的能力（分水岭技能——「优化查询 40%」要说成「分析师每天提前两小时拿到报表」）；③ 主人翁意识 + 一点叛逆（敢推十倍级改良）。招「好奇的推土机」，不招「精致的工匠」。AI 时代的标志性技能是**评估体系（evals）**。

## 二、工作流程：一次交付的六个阶段

沿一次真实交付的旅程：**找对问题 → 赢得客户 → 激活部署 → 守住续约 → 扩大收入 → 规模化复制**。各阶段要点如下；完整框架与反模式清单见 `references/workflow-1-land.md`（阶段 1-3）与 `references/workflow-2-expand.md`（阶段 4-6）。

### 1. 解决正确的问题
目标：写第一行代码前，确认问题值得解决且解决得了。
- **影子工作法**：下现场跟完真实用户的一天，看「变通」不看「流程」——每个变通都是一次系统失败；绕过被信息部/采购「翻译过的痛点」。
- **PSF 三关**（必须在现场过）：痛点（某个具体的人的具体的痛，最好是 CEO 前五关注）／经济性（每周吃掉多少人时）／可行性（数据在哪、准确率门槛多少）。
- **MVD（最小可行部署）三军规**：真实数据无例外；缩小范围不缩价值；周级死线倒逼取舍。先建评估题库再谈上线。
- 反模式：PoC purgatory（无限期、无指标、无裁判的概念验证坟墓）；用脱敏样例数据验证；解决「演示效果好」而非「值钱」的问题。
- 三类高危信号（中两条即警惕）：无主之地／只许看不给碰／宇宙级需求。

### 2. 赢得客户
目标：把验证过的单点价值变成合同和一段真正开始的关系。
- 选**灯塔客户**（成功后愿公开站台才算数），排查**需求蝗虫**（偏离战略/当廉价外包/政治消耗大）。
- **进场尽调五份地图**（1-2 周）：数据（哪个被信任）、流程（耗时/出错/情绪最激烈的三个点位）、组织（找知识枢纽）、系统、**政治**（动了谁的奶酪，给受损者安排新生路）。
- 提前打通采购/法务/安全三道闸门（预答白皮书抢出两个月）；**提案倒金字塔**：业务结果一段话 → 价值验证路径（含每阶段退出机制，「我们敢被检验」）→ 交付方法 → 风险与对策。
- 红线：单份合同十万美元以上模式才成立；按战略价值而非合同金额排期。

### 3. 激活部署
目标：目标用户形成稳定使用习惯——**撤场三个月后没人催、系统依然被高频使用**（否则是伴舞，不是激活）。
- 上线 ≠ 激活；警惕「双轨制」：官方系统空转、影子 AI 横行。
- **热修复文化**：反馈直达写代码的人、不隔传话筒；迭代按「使用阻塞度」排，不按「功能重要度」排。
- **评估体系三步**：从客户真实案例长出来 → 业务方当评委 → 接进生产回路持续打分告警。用户敏感的不是平均质量，是质量的稳定性。
- **降门槛四手法**：寄生在已有界面／默认值里藏激活率／「问 AI」翻译成「点按钮」／先副驾驶再自动驾驶（警惕审批疲劳：93% 弹窗被直接批准，护栏要做到系统底层默认拒绝）。
- 集成当战役打：数据问题先于模型问题（企业数据问题九成五是接入/清洗/关联）；知道何时绕开而非攻克。
- **变革管理三组人**：支持者（给材料、给战功）／影响者（让其成为共同作者）／受损者（提前设计出路，否则成为最顽强的地下抵抗与续约反对票）。

### 4. 守住续约
目标：让续约成为交付质量的自然结果，「关系变质」从突然死亡变成可监测曲线。
- 五类流失风险：价值蒸发／支持者离场／质量漂移／成本反噬／供应商戒断。
- SLA 做成客户可自查的面板；事故诚实通报（客户能接受事故，不能接受隐瞒）；账单变痛前先把价值账算给财务。
- **有损服务**：对长尾需求敢说不（用户数×频率不值终身维护、又不能泛化 → 给变通不给代码）。
- **培训培训师**：真正要培训的只有「会去培训别人的人」；交付做到最后，是教会客户教自己。
- 关系网格化（单点是高危，三点成网）+ 健康分每周全量巡视 + QBR 讲客户的语言、让客户业务方当主角。
- 裁判指标：**NRR** >100% 及格、≥120% 优秀（Palantir 139%）。

### 5. 扩大收入
目标：在成功部署的地基上进攻——免费验证转付费、计价对齐价值、一个部门做成一张网。
- 免费验证要有**毕业标准**且先于开工排进日程；免费期就用价值语言埋价格锚点（「本月释放约 120 人时」）；给不转正设计体面出口。
- **计价四档进化链**：按用量 → 按任务 → 按结果 → 按价值分成；越贴近价值天花板越高，测量与信任成本也越高。评估体系即计费基础设施。合同五要素缺一不可（指标定义/基线与窗口/判定方/仲裁/流产条款）。
- **先登陆后扩张**三方向：横向（相邻团队）／纵向（执行层→决策层——只被基层喜爱的系统在预算季没有辩护者）／纵深（辅助工具→核心流程）。
- 超量**变惩为奖**：阶梯折扣、主动升舱、把省下来的功劳还给客户。结构性警告：赚「创造价值」的钱长久，赚「客户离不开你」的钱迟早被清算。
- 中国市场注脚：混合制才是活路——按阶段交付验收 + 价值指标写入验收标准。

### 6. 规模化复制
目标：每做完一个客户，下一个更好做——不靠加人。**FDE 模式成立的标志：每个后续客户的定制量递减**（麦格鲁）。
- **三级杠杆**：知识复制（打法手册）→ 组件复制（连接器/评估框架/部署模板）→ 产品复制（平台能力）。前两级降低交付成本，第三级消灭交付成本。**手册管判断，组件库管手艺，平台管能力。**
- 失败资产化：复盘无罪化（挂钩绩效 → 修饰失败 → 毫无教学价值）；教训结构化进手册「雷区」章节；脱敏外传（「我们已为这个行业的弯路付过学费」）。
- 打法手册三属性：长在流程里不躺在知识库里；按场景而非功能组织（七件套）；有 owner、有版本、有折旧。
- **产品化四问**：三个以上客户独立出现过吗？泛化代价小于收益吗？不会写代码的人能用吗？收编后现场还有创造空间吗？
- 人的复制：FDE 组织养不出来就买不到（模糊问题拆解面试筛苗 + 轮岗养成）；最好的池子：解决方案架构师/技术顾问/客户侧明星用户。
- 财务体检：交付毛利率**逐年上升**比绝对值更说明模式成不成（不上升的 FDE 是咨询公司）；人均营收阶梯：外包 ~5 万 → 咨询 ~9 万 → FDE ~100 万美元。

## 三、指标（每项目只盯 3-5 个）

四层指标体系（完整口径见 `references/workflow-2-expand.md` 附录A节）：

- **交付层**：TTV 价值实现时间（MVD 以周计、完整部署以月计——FDE 生命线）；PoC 转化率（Palantir 5-10% → ~75%）；评估达标率。引用解决率前先问三件事：分母是什么、判定窗口多长、谁来判定——**口径不清的 86% 不如口径清楚的 51%**。
- **客户层**：激活率（分母是目标用户群，不是账号数）；使用深度（自助探索行为出现是最珍贵信号）；支持者覆盖数（单点高危，三点成网）。NPS 慎用。
- **商业层**：NRR（最终裁判）；交付毛利率趋势；定制递减率（连续三个客户不降 → 检视产品回流机制）；LTV/CAC 须配合 NRR 一起读。
- **组织层**：现场到产品回流速率（模式「灵魂器官」的心跳）；资产复用率；团队续航（烧干了，前面所有指标都是烟花）。

纪律：基线第一天采集，错过永不再来；指标与客户共建共认；每半年检修指标体系本身。

## 四、职业道德六条底线

1. 数据主权属于客户——能不看的就不看，能脱敏的就脱敏。
2. 诚实报告结果，包括坏消息——立身之本是「敢被检验」。
3. 不制造依赖、不贩卖恐惧——交付终点是客户自己跑得动。
4. 把「被替代的人」当回事——「技术是中立的」不是借口。
5. 对客户要求但不该做的事说不——说不的底气来自账上有别的客户。
6. 记住你代表的是「技术」本身——每次夸大都在透支行业信用，每次兑现都在存款。

灰色地带的态度：不追求道德纯洁也不转身退出，而是**待在房间里**——保住决策桌上的一票。

## 使用本 skill 的方式

- 回答「FDE 是什么」：用第一节的定义 + 划界表，强调「生产代码非报告」与「双重使命」。
- 评估/设计一次交付：按六阶段顺序过一遍，重点核对各阶段的反模式与成功判断标准（撤场后仍被使用、NRR、定制递减）。
